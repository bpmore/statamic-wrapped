## Where things live

This repository is a **standalone Statamic addon**, developed outside any site and
linked into a host site through a Composer path repository (the layout Statamic's
docs recommend for addons reused across projects).

- **This repo** is where the code and the git history live. Work happens here.
- **The host site** is where anything needing a booted Statamic is run.

```
~/Herd/
  statamic-dev/            <- host site. Run `php please` here.
  statamic-wrapped/        <- this repo. Edit code here.
```

The host site's `composer.json` has a path repository pointing at this directory,
and Composer symlinks it — so edits here are live in the site immediately. There is
**no reinstall or rebuild step** after changing addon code.

## Build commands

<!-- Replace the paths and commands with the real ones for this setup. -->

- Tests, from this repo: `vendor/bin/pest`
- Static analysis, from this repo: `vendor/bin/phpstan analyse`
- Formatting, from this repo: `vendor/bin/pint`
- Control panel assets, from this repo: `npm install && npm run build`
- **Statamic commands run from the host site**, not here:
  `cd ~/Herd/statamic-dev && php please <command>`
- If Composer changes are needed in the host site:
  `cd ~/Herd/statamic-dev && composer update bpmore/statamic-wrapped`

Do not run `php please` from this repo — there is no Statamic application here,
and it will fail.

## Working agreement for unattended runs

- **Read `PROGRESS.md` first.** It is the source of truth for what is done and what is next — more so than anything you remember from earlier in the session.
- **Do the next unfinished task, and only that task.** Do not run ahead into later phases, even when they look easy. Small, verified steps survive interruption; large ones don't.
- **Before you stop, always:**
  1. Update `PROGRESS.md` — tick the task, and record anything surprising under Notes.
  2. Confirm the repo builds and the test suite passes.
  3. Commit, with a message naming the task you completed.
- **Never end a task with the repo in a non-building state.** An unattended run may not resume for hours; leaving it broken wastes the whole next cycle.
- If a task turns out to be wrong or blocked, **write that under Notes in `PROGRESS.md` and stop.** Don't improvise a different plan — a stopped run with a clear note is far more useful than an autonomous detour.
- When every task is complete, put the line `ALL TASKS COMPLETE` at the top of `PROGRESS.md`.

## Compact Instructions

When compacting, preserve:

- The current state of the task list in `PROGRESS.md`
- Which files have been modified in this session
- The most recent test output and whether it passed
- Any decision recorded under Notes
